# Corpus — charter and authoring conventions

The law that governs `corpus/`, kept apart from the instrument that enforces most of it: what a fixture is for, what its twin owes, and the conventions a gate cannot check. Completeness is never recorded here — the audit measures it live (`bun run audit`), and a number copied into prose rots into a false certificate. The build plan that produced the corpus is gone with its work; the filing commits are the history.

## The charter

**Claims are tests, populations are the audit.** A test asserts one claim and must be GREEN; the audit measures a POPULATION against a denominator and may be RED. Capability is not the line — `check.test.js` drives `rip check` over tsgo, and the `test/toolchain` suites drive the real LSP. What a test cannot hold is the answer's SHAPE: a census over a closed set is a report, and gating its number blesses a baseline while losing the actionable list; a red held by agreement is expressible only by asserting the wrong behavior as current, which inverts when the bug is fixed. So a lone reproducible defect with a known-correct answer belongs in a test — the audit's job is to FIND it, not hold it.

**A census yields CANDIDATES, not obligations.** The suites partition by QUESTION: the battery owns behavior and emitted bytes, `test/lang` and `test/schema` own the face's TEXT, this corpus owns whether that face type-checks and answers. A spelling gated elsewhere can still be dark here, and only that gap is this corpus's — `::` is the worked example: its emission, declaration text, and decline classes are gated in [prototype.rip](../battery/prototype.rip), leaving the call sites and hover. Every candidate passes this triage before authoring.

**Where no syntactic denominator exists, a registry replaces it, by ruling.** Checker semantics (narrowing, inference enforcement, the component consumer face, schema projection) are ruled into CLAIMS.md's Behaviors before a fixture exists. Interaction shapes are ruled cells checked against the containment matrix, bounded by the gate's curated head list. The schema body is pins-or-nothing by architecture — `Schema → SCHEMA_BODY` is one production, sub-parsed at lexer-rewrite time, so RULINGS.md governs its answers while `test/schema/schema-types.test.js` gates the face's text. Runtime behavior is out of scope: the battery and runtime suites own it, and the audit's `runtime` dimension proves only that each fixture executes.

**Grammar credit** goes to `corpus/grammar/` fixtures alone, so neither an error nor a claims fixture can cover a production by accident. The claims bucket's mirror standard: every `corpus/claims/` fixture must be a named carrier of at least one CLAIMS.md row, judged live. The grammar bucket numbers from 01 and the claims bucket from 20, so the prefix says which charter a fixture answers to; basenames stay unique corpus-wide — twins, pins, and carriers all key on them.

**The corpus retires.** The unique-contribution line names any fixture the rest already covers, so completeness is not a ratchet — a healthy corpus counts every fixture as reducing a production no other does.

## Comments

One convention, every file in every bucket. A comment is never a reflowed paragraph: **no sentence spans two lines**, however long the line. A **header** is one line — the file's name and what it covers in a phrase. A **section divider** is `# ── … ──`, opening and closing on its own line, enforced by `corpus.dividers`. A **note** is one line at the shape it concerns, and exists for exactly one reason: the construct is written oddly, or is absent, because of an open defect — the one thing a reader cannot reconstruct from the code, and the thing a cleanup would otherwise undo. **Twins** mirror the .rip's dividers so the pair reads side by side; an error pair's two sides change header length together or the line alignment breaks. Header length is a **gauge**, never a gate: any cap would be a threshold with no denominator, and satisfying a tripped one means deleting prose, which points authors at exactly the notes worth keeping.

**Comments state what no instrument can:** a fixture comment earns its place by answering why a spelling is written the odd way it is, not by describing a lowering the twin already states exactly, restating a byte pin, or narrating a defect that has been fixed. Where coverage rests on a property a later author could quietly break — a list that must hold only literals, a read that must chain onto a construction — move the property into the battery as a byte pin rather than warning about it in prose: a comment asks the next author to be careful, a pin does not care whether they were.

## The register

Explicit call parens by default (the implicit spelling stays covered densely in `02-operations`), single quotes unless interpolation forces double, padded braces on inline object and type literals in both pair members, negatives in the family's error fixture and never inline. Density follows starvation — grammar-dark families get minimal-honest coverage, shape-starved ones (components, schema) get dense, real-shaped content. Every coverage claim goes through the grammar audit: **verified, never asserted.**

## Oracles

Hand-written twins, written WITH the fixture. The reactive twin is plain TS (`:=` → `let`, `~=`/`=!` → `const`), honest because the editor's ruled answers are value types — with one exception, in the ERROR pair only: a wrong annotated initializer is checked at the lowering's own call, so `12-reactive.errors.ts` spells those two lines as a call with a pinned parameter and an arrow with a pinned return; a plain declaration models a different relation and blames the name. Where a write re-fires an effect the twin hand-replays the flush, so runtime parity there asserts a predicted trace. Analogy twins for `13-components` (TSX) and `14-schema` (zod), scoped to where the analogy is honest. Positive twins are STANDARD-TS-formatted, never line-parity with the `.rip`: correspondence is by construct order and symbol name, the fixture is never edited for the twin's sake, and the twin running longer is desired. Error pairs stay strictly line-aligned, because the Diagnostics Audit derives positions from them. Everything rip-native is pinned per RULINGS.md.

## Negatives

A negative test is an unsuppressed program plus an asserted diagnostic — TypeScript's own model.

- **The pair.** Each family file pairs with an unsuppressed `corpus/errors/NN-family.errors.rip` beside its twin, LINE-ALIGNED, with an `@ts-nocheck` pragma pair that is lane-stripped and lane-enforced. A blank line separates setup from the `wrong*` variables; names are full words in both members (`wrongArgument`, never `wrongArg`).
- **Asserted, and derived.** Every diagnostic's code AND position, derived from tsgo's run over the twin — never hand-authored where a twin can judge. The lane structurally owns what no other check can reach: columns, the emitter's decline classes, and negatives that would crash the runtime dimension.
- **Positives are error-free absolutely.** Zero published diagnostics, no marker accounting, no `@ts-expect-error`. The directive stays in rip on its own merits, gated by `check.test.js` and the editor suite, but the corpus does not depend on it.
- **Rip-native negatives are pinned**, exactly where no twin can judge: components and schema, code and position, under the hover-pins discipline and gated on RULINGS.md. Reactive is HYBRID — twin-judgeable rows stay derived, and only the lowering's extra diagnostics (the `:=`/`~=` second publish) carry pins in `error-pins.json`.
- **Outside the walk.** `corpus/errors/` sits outside the shared fixture walk, twice necessary: verdict demands zero unsuppressed errors, and error fixtures must not earn grammar credit.
- **Falsifiability is contractual.** Every type-vocabulary class the positives use must carry an error-lane instance, or it paints red. The vocabulary is TypeScript's own type grammar, classified in-process each run by TS type-AST node kind — a closed taxonomy, never curated, never stale.

## Type sub-language boundaries

Excluded by design, with the lexer's own errors as reasons: template-literal types (the backtick is rip's token) and construct signatures (`(new () => T)` is the surviving spelling). Import types resolve `.rip` module specifiers in type position. Position-constrained but expressible: constructor and abstract-construct types only inside parentheses in an annotation or after `as`, and `this`-types only as a class method's return annotation. Mapped types, inline method signatures and type predicates are expressible in every position TypeScript puts them, declaration bodies included. Census-queue authoring uses the surviving spellings; both member layouts reach the census, because the grammar audit classifies through the compiler's own `renderTypeDecl` rather than rip's source text. The `.ts` seam is verified both polarities: an exotic alias imports into rip by NAME, and a wrong assignment draws TS2322 spelled in the exotic type, positioned on the rip line.
